# 修复新建标签页中 `$$` 公式偶发不渲染（被误判为非公式文本）

## Context（根因）

用户反馈：新建 md 文件标签页里，LaTeX 公式**有时候**不渲染，像是不识别 `$$`，且无法稳定复现。

排查结论（解析、渲染链路均为确定性逻辑，浏览器探针 100 轮解析 + 12 个编辑器实例零失败）：

1. remark-math 对**同一行**的 `$$内容$$` 一律解析为 **inlineMath（行内公式，双 `$` 定界符）**；只有多行围栏形式才生成块级 `math` 节点。已用 node 实测确认：
   - `$$1+1=2$$` → `inlineMath["1+1=2"]`
   - `$$\nx^2\n$$` → 块级 `math["x^2"]`
2. 项目自定义的误报守卫 [math-guard.ts](file:///d:/Trae_project/ColaMD/src/renderer/editor/math-guard.ts) 会把"不像 LaTeX"的行内公式**退回成字面文本**。其 `looksLikeLatex()` 只接受：含 `\ ^ _ { }`、纯字母/空格、字母+运算符。
3. 因此**纯数字/运算符公式全部被拒**：`$$1+1=2$$`、`$$3*4$$`、`$$123$$` 等 → 退回字面文本，界面直接显示 `$` 符号；而 `$$x^2$$`、`$$S=ab$$` 正常。**"时好时坏"实际由公式内容决定**，与标签页无关（新标签页默认在源码模式书写，最容易遇到）。
4. 守卫还有一个连带缺陷：退回文本时硬编码写死成**单 `$`**（第 23 行 `` `$${value}$` ``），即使用户原文是 `$$..$$`——违反"输入字符忠实原样"原则，`$$123$$` 会被改写成 `$123$`。
5. 该守卫被三条管线共用，修一处全覆盖：编辑器解析 [editor.ts#L2159](file:///d:/Trae_project/ColaMD/src/renderer/editor/editor.ts#L2159)、docx 导出 [docx-export.ts#L1167](file:///d:/Trae_project/ColaMD/src/main/docx-export.ts#L1167)、canvas 导入 [import-markdown.ts#L54](file:///d:/Trae_project/ColaMD/src/renderer/canvas-editor/markdown/import-markdown.ts#L54)。

补充事实：remark-math 序列化器会把行内 `$$x$$` 规范化为 `$x$`（既有行为，所有行内公式皆然），所以修复必须让规范化后的单 `$` 形态同样能通过守卫，不能只放行双 `$`。

## 修改方案（仅一个文件）

文件：[math-guard.ts](file:///d:/Trae_project/ColaMD/src/renderer/editor/math-guard.ts)

### 1. `looksLikeLatex()` 增补"纯数字算式"规则

在现有三条规则后追加：值中含数学运算符 `= + - * /` 即判定为公式：

```ts
// 纯数字算式也算公式：$1+1=2$、$3*4/2$
// 原守卫只认含字母的算式，导致 $$1+1=2$$ 退回字面文本（"$$ 不渲染"）。
// 不含这些运算符的纯数字/标点（$5.00、$123$）仍按货币/散文处理。
if (/[=+\-*/]/.test(value)) return true
```

保持既有反例继续被拒：`价格 $5，成本 $6`（值含中文/逗号，无运算符）、`$5.00 | $6.00`（只有 `|`、`.`、空格）。

### 2. 双 `$` 定界符无条件视为公式

remark 转换器签名由 `(tree)` 改为 `(tree, file)`，利用 `node.position.start.offset` 从 `file.value` 切出节点原文；原文以 `$$` 开头则**直接保留**（双美元符没有货币用法，等于用户明确声明公式；与 Obsidian 行为一致），不调用 `looksLikeLatex`。

### 3. 退回字面文本时保持原始定界符（字符忠实）

确需退回时（单 `$` 且不似公式），文本节点优先写回**原始切片**（含用户原本的 `$` 或 `$$`）；仅当拿不到 position/file 时才回退到旧的 `` `$${value}$` ``。

### 不做的事

- 不把单行 `$$x$$` 转成块级 math_block（会改动文档结构并在序列化时改成多行围栏，超出本问题范围；行内渲染已满足"公式能渲染"）。
- 不改 remark-math 序列化的 `$$ → $` 规范化（影响全部行内公式，风险大且不影响渲染结果）。
- 不新增 wysiwyg 输入规则（保持"所见即所得中敲字符即字面字符"的既有设计）。

## 关键用例（预期行为）

| 源码 | 修复前 | 修复后 |
|---|---|---|
| `$$1+1=2$$` | 字面文本（且被改成 `$1+1=2$`） | 渲染公式 |
| `$$3*4/2$$` | 字面文本 | 渲染公式 |
| `$1+1=2$`（规范化后） | 字面文本 | 渲染公式 |
| `$$x^2$$` / `$a+b=1$` | 渲染 | 渲染（不变） |
| `价格 $5，成本 $6` | 字面文本 | 字面文本（不变，误报防护保留） |
| `$5.00 \| $6.00` | 字面文本 | 字面文本（不变） |
| `$$123$$`（无运算符/字母） | 字面文本且字符被改 | 双 `$` → 渲染公式；原文不再被改写 |
