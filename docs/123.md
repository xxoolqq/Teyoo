# 导入中心审查卡：这些字段的数据来源与格式

**一句话结论**：除「来源」是自由文本外，截图里的每个下拉都是**主进程里的受控词表** —— 模型只能从里面挑（值由 prompt 约束），主进程还会再校验一遍，渲染端拿到的只是「当前目录」这一份转述（`math-parse-catalog`）。

---

## 1. 逐项对照

| 控件（截图） | 显示值 | 唯一数据来源 | 格式 | 能否手改 |
|---|---|---|---|---|
| 题型 | 单选题 | `QUESTION_TYPE_OPTIONS`（`src/main/math-parse/parse.ts:118`） | `{ value, label }[]`，4 项 | 能，四选一 |
| 难度 | 易错题 | `DIFFICULTY_OPTIONS`（`src/main/math-parse/parse.ts:126`） | `{ value, label }[]`，4 项 | 能，四选一 |
| 来源 | 2026 高考一卷-数学 | 模型输出的 `source`；为空时用「试卷标题」输入框兜底（`src/main/math-parse/parse.ts:555`） | 自由字符串 / `null` | 能，纯文本 |
| 学段 | 必修一 | `CURRICULUM` 的**第一层 key**（`src/main/math-parse/curriculum.ts:18`） | `Record<册, ...>`，5 册 | 能，五选一 |
| 章节 | 1. 集合与常用逻辑用语 | `CURRICULUM[册]` 的 key | `Record<章, 小节[]>`，全树 18 章 | 能，随册联动 |
| 小节 | 1.3 集合的基本运算 | `CURRICULUM[册][章]` 的数组元素 | `string[]` | 能，随章联动 |
| 知识点分类（截图上半块） | 平均数、中位数、众数 | 模型输出 `knowledge_points[].code` → 用 `KNOWLEDGE_CATALOG` 回填展示名（`src/main/math-parse/catalog.ts:26`） | `[code, name, ...aliases]`，约 230 条 | 只能调「主要/辅助」或移除 |

下发通道在 `src/main/index.ts:2049-2057`：主进程把 `CURRICULUM` + 两份枚举一次性发给渲染端，词表（20KB+）不进渲染端 bundle。

## 2. 具体格式与样子

### 2.1 题型 / 难度

值和文案写在同一处，避免「下拉里没有这个值」这种只在界面上表现为空白的事故。

```ts
export const QUESTION_TYPE_OPTIONS = [
  { value: 'single_choice',   label: '单选题' },
  { value: 'multi_choice',    label: '多选题' },
  { value: 'fill_in_blank',   label: '填空题' },
  { value: 'detailed_answer', label: '解答题' }
] as const satisfies readonly { value: QuestionType; label: string }[]

// normal（常规题）只为下拉与 MathBank 对齐（四档）；拆题模型不会输出它
export const DIFFICULTY_OPTIONS = [
  { value: 'easy_error', label: '易错题' },
  { value: 'normal',     label: '常规题' },
  { value: 'challenge',  label: '挑战题' },
  { value: 'qiangji',    label: '强基题' }
] as const satisfies readonly { value: Difficulty; label: string }[]
```

> 注意：`normal`（常规题）是「人选的档」，模型只出另外三档 —— `src/preload/index.ts:112-114` 的注释写明了这一点。

### 2.2 教材三级（人教 A 版，顺序有语义）

```ts
export type CurriculumTree = Record<string, Record<string, readonly string[]>>

export const CURRICULUM: CurriculumTree = {
  必修一: {
    '1. 集合与常用逻辑用语': [
      '1.1 集合的概念',
      '1.2 集合间的基本关系',
      '1.3 集合的基本运算',
      '1.4 充分条件与必要条件',
      '1.5 全称量词与存在量词'
    ],
    '2. 一元二次函数、方程和不等式': [ /* 2.1 ~ 2.3 */ ],
    // …
  },
  必修二: { /* 6 ~ 8 章 */ },
  选修一: { /* … */ },
  选修二: { /* … */ },
  选修三: { /* … */ }
}
```

- 5 册：`必修一 / 必修二 / 选修一 / 选修二 / 选修三`
- 章名带序号（`"1. 集合与常用逻辑用语"`），小节名带章号（`"1.3 集合的基本运算"`）
- **逐字比对，不做任何归一化** —— 否则 `1.1` 和 `1.10` 会互相通融
- 顺序即教材目录顺序：prompt 里「多模块融合题取位置最靠后的模块」依赖这个插入顺序，所以书写顺序不能重排

### 2.3 知识点目录（编码表，不是自由命名）

```ts
export type CatalogRow = readonly [code: string, name: string, ...aliases: string[]]

export const KNOWLEDGE_CATALOG: readonly CatalogRow[] = [
  ['1015', '集合的含义', '集合'],
  ['1028', '集合包含关系的判断'],
  ['1042', '补集运算'],
  ['1097', '二次函数零点与一元二次方程解的关系',
           '二次函数零点与一元二次方程解的关系【人教B、苏教、湘教】'],
  ['5046', '平均数、中位数、众数'],
  ['5049', '方差、标准差'],
  // … 约 230 条（MathBank 773 条目录里的高频子集）
]
```

- `code` 既有纯数字（MathBank 主库），也有 `local:` / `zxxk:` 前缀（外来目录），校验一律按字符串精确比对，不做前缀特判
- 别名只帮模型认出「同一考点的不同教材叫法」，不参与校验
- `name` 由目录回填，**不信模型给的名字**（`parse.ts:26`）

### 2.4 模型输出 → 卡片上的题目对象

模型按 prompt 返回 JSON，主进程归一化成 `MathParseQuestion`（`src/preload/index.ts:104-117`）：

```json
{
  "content": "某班 5 名同学的身高数据为 4, 5, 6, 8, 12，则这组数据的中位数是（ ）\nA. 5\nB. 6\nC. 8\nD. 9",
  "answerMarkdown": "将数据从小到大排列：4，5，6，8，12。\n\n共有 5 个数据，中位数为第 3 个数，即 6。",
  "questionType": "single_choice",
  "categoryCompulsory": "必修一",
  "categoryChapter": "1. 集合与常用逻辑用语",
  "categoryKnowledge": "1.3 集合的基本运算",
  "difficulty": "easy_error",
  "source": "2026 高考一卷-数学",
  "referencedImages": [],
  "knowledgePoints": [
    {
      "code": "5046",
      "name": "平均数、中位数、众数",
      "role": "main",
      "evidenceSource": "content",
      "evidence": "这组数据的中位数是",
      "targetEvidence": ["中位数"],
      "reason": "题干直接要求求中位数"
    }
  ]
}
```

`knowledgePoints` 的元素结构（`src/main/math-parse/parse.ts:24-34`）：

```ts
interface ParsedKnowledgePoint {
  code: string                                  // 目录里的稳定编码
  name: string                                  // 按目录回填的展示名
  role: 'main' | 'auxiliary'                    // 主要考查 / 辅助涉及
  evidenceSource: 'content' | 'answer_markdown' // main 只能来自题干，auxiliary 只能来自解析
  evidence: string                              // 引文
  targetEvidence: string[]                      // 引文里命中的关键词
  reason: string
  scope?: string
}
```

### 2.5 落库后的样子

点「导入此题」后写 `userData/question-bank.db`：`source` 为空则存 `null`，`knowledgePoints` 落到关联表 —— 「本地题库」卡片上那行「知识点 · 主要/辅助」就是从关联表读回来的。

## 3. 校验规则（为什么必须从词表里选）

| 情况 | 处理 | 结果 |
|---|---|---|
| 学段/章节/小节不在 `CURRICULUM` 里 | 降级并记 warning | 下拉显示「××（不在当前目录）」，值不丢 |
| 知识点 `code` 不在 `KNOWLEDGE_CATALOG` 里 | 丢弃该点 | 出现「模型引用了不存在的知识点」类 warning |
| `role=main` 但引文来自解析 | 强制改成 `content` | 记 warning（引文位置本身能自证） |
| 模型没给 `source` | 用「试卷标题」兜底 | `source = 标题`；标题也空则 `null` |
| 题型/难度不在枚举里 | 丢弃该题或回退 | 记 warning |
| 答案未标 `[EXTRACTED_ORIGINAL]` | 「不生成」模式清空；生成模式按 AI 生成处理 | 来源标记只参与判断，不写进答案正文 |

所以截图上这六个框里的值，本质上都是「**词表里的某一项**」；只有「来源」是模型从试卷正文里读出来的原文（读不到时退回你填的试卷标题）。
