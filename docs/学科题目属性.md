# 学科题目属性设计（大白话版）

> 这份文档把前面几轮讨论的东西整理成一个能直接拿去开会、拿去改代码的说明。
> 不讲术语，尽量用大白话 + 例子。看完应该能回答三个问题：
> 1. 为什么现在这套只够数学用？
> 2. 加英语、语文、历史这些学科，到底要动哪里？
> 3. 那些"没法列清单"的学科，怎么让它既好用又不乱？

---

## 0. 一句话总结

**数学靠"选项固定"来保证质量（只能从一张清单里挑），开放学科靠"格子固定、内容可长"来保证质量（格子必须是那几个，格子里填什么先放开，之后再慢慢归拢）。**

这两种做法不是谁替代谁，而是同一个系统里不同字段用不同的严格程度。

---

## 1. 现在的问题：一套词表只喂得饱数学

### 1.1 现在有什么

| 东西 | 在哪 | 长什么样 |
|---|---|---|
| 教材目录 | `src/main/math-parse/curriculum.ts` | 人教 A 版，必修一/二、选修一/二/三，共 18 章，每章下面挂小节 |
| 知识点清单 | `src/main/math-parse/catalog.ts` | 约 230 条，每条是「编码 + 名字 + 别名」，比如 `['5046', '平均数、中位数、众数']` |
| 题型 | `src/main/math-parse/parse.ts` | 单选、多选、填空、解答，共 4 个 |
| 难度 | 同一个文件 | 易错、常规、挑战、强基，共 4 档 |

模型拆题时，我们把这些清单塞进提示词，并告诉它："你只能从这些里面挑"。
挑完之后，本地还会再检查一遍：这条编码存在吗？这个章节名对得上吗？对不上就降级或者丢弃，并给一条提示。

这就是现在能保证质量的原因——**不是模型聪明，而是它的选择被限制得很死**。

### 1.2 为什么数学能这么干

因为数学的考点本质上是一份**动作清单**：

- 求集合的补集
- 判断函数的单调性
- 求椭圆的离心率

这类东西是可以数清楚的，数出来大概七八百条，一份清单能装下。所以"只能从清单里挑"这句话，对数学是成立的。

### 1.3 为什么别的学科不能这么干

拿英语举例。一道阅读理解：

- 它考的是"细节理解"还是"推理判断"？
- 话题是"环境保护"还是"校园生活"？
- 语篇是"记叙文"还是"应用文"？
- 语法上涉及"定语从句"还是"一般过去时"？

**四个问题都成立，而且互相不替代。** 你没法把它归到"某一个考点"下面，因为英语的题目本来就是多维度同时命中的。

语文更明显：一篇散文阅读，可能考"表现手法"、考"语言赏析"、考"主旨理解"。这些东西没有一份权威清单能把它们整齐列完，而且不同老师叫法还不一样（"表现手法" / "写作手法" / "艺术手法"）。

历史、政治、地理也一样：一道材料分析题，横跨"政治制度 + 经济背景 + 史料实证"，你让它挂一个点，等于把信息砍掉四分之三。

**所以问题不是"词表不够大"，而是"这些学科的题目本来就不是单点归属"。**

## 2. 核心思路：学科包

### 2.1 什么是学科包

用户上传试卷之前，先做一次简单选择：

```
学科：初中英语  →  教材版本：人教版
```

这两个选择（加上自动带出的学段）就决定了一个"包"（下称 **学科包**）。学科包里装着这个学科这个学段需要的所有东西：

- 教材怎么分层（英语是「册 → Unit → Section」，数学是「册 → 章 → 小节」）
- 有哪些题型（英语有完形填空，数学没有）
- 有哪些"格子"（英语要语法、话题、语篇、技能四个格子；数学只要考点一个格子）
- 拆题时给模型的提示词片段
- 本地校验的规则（数学教材位置必填，英语允许"不归属教材"）

**关键点：选完这一次，后面的下拉、提示词、校验全部跟着换，而且三处读的是同一份数据。**

如果界面能选但校验不认，就会出现"选了个题型、结果导入报错"这种最难解释的问题。所以"三处同源"是必须要守住的底线。

### 2.2 为什么用"包"，不直接按学科写死分支

如果不用包，而是每个学科加一套 `if` 判断，很快会变成：

```
if 数学 → 用这套题型
else if 英语 → 用那套题型
else if 语文 → …
```

每加一个学科要改四五个地方，而且改漏一处就出 bug。

用"包"的方式，加一个学科 = **加一个数据文件**，代码不用动。这是最省事、也最不容易出错的扩展方式。

### 2.3 一个学科包里有什么

| 项目 | 大白话解释 | 数学的例子 | 初中英语的例子 |
|---|---|---|---|
| 教材结构 | 这本教材怎么分层的 | 册 → 章 → 小节 | 册 → Unit → Section |
| 题型 | 这个学科会出哪些形式的题 | 单选、多选、填空、解答 | 单项选择、完形、阅读、七选五、语法填空、书面表达… |
| 格子（维度） | 一道题需要挂几个标签 | 只要"考点"一个 | 语法、话题、语篇、技能四个 |
| 提示词片段 | 拆题时给模型的额外交代 | 公式要锁住、考点只能从清单挑 | 不锁公式、听力题先占位 |
| 校验规则 | 哪些字段必须有、哪些可以空 | 教材位置必填 | 教材位置可以空 |

## 3. 九门学科的公共维度

语数外物化生史地政，虽然内容差得远，但**"一道题该怎么描述"这件事，结构是相通的**。

分两类说：一类是"结构一样，值也一样"（可以直接做死），一类是"结构一样，值各学科自己定"。

### 3.1 结构一样、值也一样的（可以直接固定）

| 维度 | 大白话 | 为什么九科通用 | 严格度 |
|---|---|---|---|
| **题型** | 这道题是选择题还是作文题 | 都是"选择 × 填空 × 简答 × 写作"这个骨架 | 很严（只能选） |
| **难度** | 这题难不难 | 易错、常规、挑战、强基四档，跟学科无关 | 很严 |
| **认知层级** | 这题是要你"记住"还是"推理" | 课标和考试评价都用这套话 | 很严 |
| **作答形式** | 机器阅卷还是人工阅卷 | 客观题 / 主观题，由题型就能推出来 | 很严（可自动推） |
| **分值** | 这题几分 | 每科都有 | 数字 |
| **题位** | 第几题、第几大题 | 卷面结构，每科都有 | 数字 |
| **来源** | 哪年、哪个地区、什么考试 | 年份 + 地区 + 考试类型 + 卷别 | 很严（四段结构） |
| **教材位置** | 这题对应教材哪一课 | 都是三层（册 / 章或单元 / 节或课），但**层名可配、允许空** | 结构严，内容各科定 |

**这里要特别说"认知层级"这个维度。**

很多人第一反应是"知识点才是核心维度"，其实不是。知识点各科差异巨大，但"这道题考的是记忆还是推理"是九科都成立、而且能直接支撑分析的。

举几个例子：

- 语文默写"落霞与孤鹜齐飞" → 识记
- 物理"用牛顿第二定律算加速度" → 应用
- 历史"结合材料分析该政策的影响" → 分析综合
- 政治"评析某观点" → 评价

有了这个维度，你可以回答"这套卷子是背多还是想多"，这个分析跨学科都有意义。

### 3.2 题型要说明一句

题型是"公共骨架 + 各学科加料"，不是九科完全一样的清单：

```
公共部分：单项选择、多项选择、填空、简答/解答、材料分析、写作
各科加料：
  英语 → 听力、完形填空、七选五、语法填空、读后续写
  语文 → 默写、古诗文阅读、语言文字运用、作文
  物理化学 → 实验探究、计算题
  生物 → 遗传图解、实验设计
  历史 → 小论文、史料实证
  地理 → 读图分析、区域综合
  政治 → 辨析、评析、建议类
```

所以包里存的应该是"公共项 + 本学科扩展项"，而不是全部重写一遍。

### 3.3 结构一样、值各学科自己定的

| 维度 | 大白话 | 谁来定值 | 严格度 |
|---|---|---|---|
| **学科模块** | 这题属于哪个大板块 | 各科课标：数学是函数/几何/概率统计；物理是力学/电磁学/热学；历史是政治/经济/文化 | 严（模块名固定，一般 4~8 个） |
| **核心素养** | 这题考的是哪项素养 | 各科课标，每科 3~5 条 | 中（维度固定，值在包里） |
| **情境载体** | 这题用什么场景包装 | 四类通用：生活实践 / 学科探究 / 学习探索 / 跨学科综合 | 严（这四类九科都适用） |
| **材料形式** | 题目给的是什么材料 | 纯文字、图表、示意图、地图、实验装置、史料、音频 | 中 |
| **跨学科程度** | 这题是单科还是跨学科 | 单科 / 学科内综合 / 跨学科 | 严 |

**"情境载体"这一条值得单独提。** 新课标这几年一直在推"无情境不成题"，九科都在出"用真实场景包装"的题。而这四类情境（生活实践、学科探究、学习探索、跨学科综合）是通用的分类，直接做死就行。

### 3.4 什么不该做成公共维度

| 东西 | 为什么不行 |
|---|---|
| 具体知识点 / 考点 | 开放学科没法列完，而且不同老师叫法不一样。这个只能"先放开、后归拢"（见第 4 节） |
| 解题方法 / 套路 | 差异太大：数学有"设而不求"，物理有"整体法"，语文有"对比阅读"，放一起没法统计 |
| 学科特有的小字段 | 比如英语的"词数"、物理的"实验器材"、地理的"区域尺度"，放包里当扩展字段，上层不用管 |

### 3.5 建议的最小公共集（9 个）

按重要程度排：

1. 学科
2. 学段
3. 教材位置（允许空）
4. 题型
5. 认知层级
6. 难度
7. 学科模块
8. 情境载体
9. 来源（年份/地区/考试类型/卷别）

前六个决定了你能做什么样的统计和筛选，后三个决定了你能不能把题定位回去、找得到。

## 4. 开放学科怎么办：格子固定、内容可长

这是整份文档最核心的一节。

### 4.1 先想清楚一件事：不是所有字段都要一样严

一张表里，有的格子必须定死，有的格子可以放开。混在一起谈"要不要词表"，就会吵不出结果。

我把它分成四档，用"门"来打比方：

| 档位 | 大白话 | 例子 | 出问题怎么办 |
|---|---|---|---|
| **L1 铁门** | 只能从清单里选，不在清单里的直接不要 | 数学考点、题型、学段 | 硬校验，错了就丢 |
| **L2 弹簧门** | 先按清单选，选不到可以自己写，但会被标记"待归拢" | 英语语法项、话题、语篇类型 | 软校验，只记账不丢 |
| **L3 提示牌** | 给个参考清单，随便填 | 历史"考查能力"、政治"核心素养" | 不校验 |
| **L4 自由发挥** | 纯文字描述，不进检索 | 考点说明、难度理由 | 不校验 |

**为什么这样分？**

因为你需要"能筛选"和"能容纳新东西"这两件事同时成立。

- 题型、教材位置这些不严，组卷就会出乱子（想抽"阅读题"结果抽出一堆作文）
- 考点如果太严，新题型、新考法一进来全被丢掉，数据就废了

分开管，各管各的，问题就没了。

### 4.2 一条标签长什么样（五个字段缺一不可）

| 字段 | 大白话 | 为什么必须有 |
|---|---|---|
| **维度** | 这是哪个格子（语法/话题/语篇/技能/考点） | 格子必须定死，不然模型能编出新格子，越跑越偏 |
| **编码** | 清单里的编号，**可以空** | 弹簧门（L2）没命中时就是空 |
| **文字** | 人看的那句话，**必须有** | 没有编码时，全靠它显示和搜索 |
| **来源** | 这条是清单命中 / 模型自己写的 / 人工确认的 | 出问题时能追责，也决定要不要进待归拢池 |
| **原文证据** | 题干或解析里能翻到的那句原话 | 开放学科唯一的自动质检手段 |

**"原文证据"这一条一定要强调。**

现在数学有编码可以校验，英语没有。那怎么防止模型瞎贴标签？

答案是：**让它必须指出标签在原文哪里**。

比如它说这道题考"推理判断"，那就要给出题干里的依据（"由此可以推断出"这类句子）。有了这句引文，人工核对成本会低一个数量级；模型想瞎编也编不圆。

这个东西项目里其实已经有了（知识点结构里的 `evidence` / `targetEvidence`），只是现在当成可选。开放学科要把它升级成**必填**。

### 4.3 三步走：先能跑 → 再归拢 → 最后定死

最忌讳的做法是：先花三个月手工编一份大词表，编完发现不符合实际命题。

正确顺序是反过来的：

**第一步：先放开（能跑起来）**

- 词表只给"格子 + 几个常见例子"，不塞几百条
- 模型爱怎么写怎么写，全部存进去，标成"模型自己写的"
- 检索先靠题型 + 教材位置 + 全文搜索

**第二步：归拢（让数据自己长出词表）**

- 后台加一个"标签归拢"页面
- 按时出现次数排序，列出还没归拢的标签（只看前 50 个就够用）
- 人工做三件事：
  - 合并同义词（"一般过去时" / "过去时" 合成一个）
  - 提升成正式条目（给它一个编码）
  - 丢掉明显错的
- 归拢后**回头改历史数据**（同一批标签一起改）

**第三步：定死（沉淀成学科包）**

- 高频稳定的标签进 L2 清单，下次解析优先命中
- 新出现的才进待归拢池

一句话：**数学是"先有词表，后有数据"；开放学科是"先有数据，再长出词表"。**

### 4.4 为什么不能一步到位

三个现实原因：

1. 你不可能提前知道学生会做什么题、老师会怎么标
2. 词表一旦定死又不好改，改一次要迁数据、改提示词、改校验，成本很高
3. 真实数据会告诉你"哪些标签其实是一回事"——这个信息只有在有数据之后才存在

## 5. 从 cn-math-taxonomy 学到的

### 5.1 它是什么

GitHub 上的一个开源项目（`xiaoyang111222/cn-math-taxonomy`），一开始只做数学，现在扩到了小学数学、初中数学、高中数学、小学/初中/高中英语、小学语文、初中物理、高中物理。

它做的事情是：

- 把知识点做成一张**图**（每个知识点是一个节点，节点之间用"先修关系"连起来）
- 每个知识点挂上课标条款、掌握标准、诊断题
- 页面上可以浏览图谱，也可以做题诊断"你哪里不行、该从哪补"

规模大概是：1800 多个知识点、2900 多条先修关系、7000 多道诊断题。

### 5.2 七个值得抄的设计

**① 知识点不是一棵树，是一张图**

它没有把知识点硬塞进教材目录，而是做成"节点 + 关系"：

- 节点：这个知识点叫什么、属于哪个领域、教材哪一章
- 关系：学 A 之前要先会 B（分"必须会"和"会更好"两档）

**对我们有什么用：** 开放学科的知识点本来就没法按目录穷举，做成图反而更自然——**可以一个一个往上加，不用一开始就凑齐**。

**② 每个知识点自带"掌握标准"和"诊断题"**

它不止是给知识点起个名字，还写清楚：

- 会到什么程度算掌握（2~3 条标准）
- 用什么题可以验证（一道小题 + 答案）

**对我们有什么用：** 标签不再只是一个字符串，而是一个"有内容的对象"。以后要做"这道题为什么被标成这个点"，有东西可讲。

**③ 每个知识点挂靠课标条款，并标注"确定 / 推测"**

它给每条课标编了稳定编号（比如 `cms-2022:4.NA.01`），知识点用 `standards` 字段挂上去，并且标明这条挂靠是"确切的"还是"推测的"。

**对我们有什么用：** 这是最该抄的一条。**"确定"和"推测"必须能区分**，否则以后做统计分不清哪些是硬数据、哪些是猜的。

**④ 编码规则按"学科 + 学段"分前缀，永不改号**

它的知识点编号是这样的：

```
cnm_p001…   小学数学
cnm_001…    初中数学
cnm_h001…   高中数学
cne_p001…   小学英语
cne_j001…   初中英语
cne_h001…   高中英语
cnc_p001…   小学语文
cnp_001…    初中物理
cnp_h001…   高中物理
```

名字可以改，**编号永远不改**。

**对我们有什么用：** 这样一来，不管学科怎么加、名字怎么改，历史数据都能对得上。加学科只是加一个前缀，不会冲突。

**⑤ 改了编号怎么办：用别名表，不改老数据**

它早期有一批外部节点，后来并进正式知识点，做法是留一张"旧编号 → 新知识点"的对照表，而不是去改所有引用。

**对我们有什么用：** 词表一定会演进（合并、拆分、改名）。**别名表比改编号安全得多**，老数据不用动。

**⑥ 跨学科关系用"引用"，不连边**

物理要用到数学知识（比如解方程），但它**不给物理图和数学图连线**，而是在物理知识点上写一个 `mathLinks`（"这道物理要用到哪个数学点"），并说明理由。

**对我们有什么用：** 跨学科如果连边，图会越连越乱。写成"引用"就清楚多了：**主关系留在本学科内，跨学科只是备注**。

**⑦ 教材版本用"对照表"，不塞进主字段**

它的 `chapter` 记的是人教版的章节位置，另外留一个 `mappings` 字段存沪教版等其他版本的对应位置。

**对我们有什么用：** 说明**教材位置只是一个"视图"，不是身份**。同一个知识点在不同版本教材里位置不同，用对照表解决，别想着把位置写进名字里。

### 5.3 它验证了我们哪些判断

| 我们说过的 | 它怎么验证的 |
|---|---|
| 开放学科要"受控增长"，不能纯自由文本 | 它用 1800 多个稳定编号覆盖了四个学科，包括语文英语这种开放学科 |
| 课标是天然骨架 | 它把 627 条课标编成稳定编号，知识点反向挂靠 |
| 学科要独立，跨学科用弱链接 | 英语单独成图，物理单独成图，跨学科只用 `mathLinks` |
| 教材位置必须允许版本差异 | 主字段 + `mappings` 对照表 |

### 5.4 我们需要修正的两处

**第一处：具体考点不该是"自由文本"，而应该是"可以慢慢长的节点表"**

我之前的说法是"考点用自由文本，事后归拢"。看了这个项目之后，更好的做法是：

- 建一张知识点表（哪怕一开始只有数学那 230 条）
- 模型可以提出新节点，但**要进待审池**，审过之后才成为正式节点
- 题目只引用正式节点；没命中时先保留原始写法，标成"模型提的"

这样比纯自由文本好管，也比"必须先编完整词表"现实。

**第二处：公共维度要补两个**

- **知识类型**：概念性 / 程序性 / 推理 / 应用 / 建模。这个比"认知层级"更贴近命题实际，九科都能填
- **置信度**：这条挂靠是"确定"还是"推测"。没有它，以后没法判断数据质量

### 5.5 不能直接抄的部分

**① 许可证不允许商用**

这个项目是 **CC BY-NC 4.0**，意思是：个人学习、教学、研究免费用，**商用要单独授权**（作者留了联系方式）。

所以：如果 Teyoo 是要卖的产品，**只能抄结构，不能抄数据**。要真用它的数据，得去谈授权。

**② 它自己说数据没审过**

README 第一屏就写着"这是 AI 生成的初稿，未经任何教师审核"。知识点粒度、掌握标准、诊断题答案，尤其是"先修关系"（哪些是必须、哪些是会更好），都需要一线教师看。

所以它的价值在**结构和工程做法**，不在"拿来即用的标准答案"。

**③ 它自己的统计数字都对不上**

仓库侧栏写"1644 个知识点、2403 条先修边、6723 道题"，正文写的是"1838 个知识点、2926 条边、7427 道题"——两边不一致。

这反过来提醒我们一件事：**统计数据要由脚本自动算出来，不要手写在文档里**。人写的数字一定会漂。

## 6. 落地顺序

不要一次全做，按这个顺序来，每一步都能单独验收：

| 阶段 | 做什么 | 怎么算成功 |
|---|---|---|
| **P0 搬家** | 把现在数学那三份常量（教材树、考点清单、题型难度）搬进一个"数学学科包"，行为一点都不变 | 同一份数学卷，拆出来的结果和改之前逐字段一致 |
| **P1 打通一个英语** | 只做"初中英语·人教版"：教材树（册/Unit/Section）+ 英语题型 + 四个格子（语法/话题/语篇/技能），公式锁定关掉 | 上传一份初中英语卷，能拆题、题型和标签基本正确、不会把 `$` 当公式 |
| **P2 建表和迁移** | 题目表加"学科 / 学段 / 版本 / 包"几个字段，新建标签表（一题多标签），老数据回填成"数学" | 本地题库、智能组卷、检索都能按学科过滤，数学题不会混进英语卷 |
| **P3 扩展** | 补小学英语、高中英语、物理化学；支持用户自己加学科包；上线"标签归拢"页面 | 加一个学科只需要加一个数据文件，不改代码 |

**P2 千万不能省。** 数据库里没有"学科"这个字段，前面几步全白做——选了"初中英语"也筛不出东西。

## 7. 需要先拍板的三件事

这三件事决定了后面怎么改，定不下来就别动手：

**① 英语的考点清单从哪来？**

人教版单元目录只能解决"这篇课文在哪个单元"，解决不了"这题考什么语法、什么技能、什么语篇"。

这部分内容得有人做：可以用《义务教育英语课程标准（2022 年版）》里的清单，再补中考真题高频考点。**这是内容活儿，不是代码活儿**，也是整个方案里最花时间的部分。

**② 教材位置允许空吗？**

我的建议是：**英语允许空，数学保持必填**。

因为英语大量题目（阅读、完形、写作）本来就不归属某个单元，硬填就是在造假数据。

**③ 一个学科包管一个学段，还是管整个学科？**

建议**一个包管一个学段**：`初中英语·人教版` 这一个包里包含七上到九全所有册，而不是"初中英语七年级上"这种过细的包。

否则下拉会变成一长串选项，用户光选就要选半天。

---

## 8. 最后再说一遍核心

回到最开始那句话：

> **数学靠"选项固定"保证质量，开放学科靠"格子固定、内容可长"保证质量。**

具体到三个动作：

1. **把格子定死**（学科、学段、教材位置、题型、认知层级、难度、学科模块、情境、来源、标签维度）
2. **把内容先放开**（考点、语法项、话题先让模型写，但要带原文证据）
3. **靠真实数据慢慢归拢**（归拢页面 + 别名表 + 定期把高频项提升成词表）

这么做的结果就是：用户只需要选一次"初中英语 / 人教版"，后面的题型、教材树、标签、提示词、校验全部自动跟着变，而且**加了新学科不用改代码**。

这也是"简单选择就能找到所有对应数据"最现实的实现方式。
